# 드레스노트 제품 기준

기준일: 2026-11-01. 현재 로컬 구현과 사용자 피드백을 반영한다. 과거 계획의 완료 표시는 이 문서의 수용 기준을 대신하지 않는다.

## 제품 목적과 범위

촬영이 어려운 드레스 투어에서 특징과 당사자의 느낌을 빠르게 기록하고, 나중에 드레스를 떠올려 선택한다. 신부와 동행인이 사용하는 320–480px 모바일 웹/PWA다. 데이터·그림 합성·PDF 처리는 브라우저 안에서 이루어진다.

계정, 서버, 클라우드 동기화, 공동 편집, 분석 SDK, 실시간 이미지 생성, 실제 피팅·체형 예측, 일반 PDF OCR은 범위에 포함하지 않는다.

길이·트레인·색상·뒷모습·뒤 파임/여밈·탈부착 소매·착용감 태그·얼굴 기능은 제공하지 않는다. 기존 데이터의 해당 필드는 읽기 호환성만 유지하며 현재 화면과 새 PDF 시각 페이지에 표시하지 않는다.

두 드레스나 두 연출을 나란히 비교하는 기능은 제공하지 않는다. 샵·전체 기록·후보 목록에서 개별 드레스를 바로 열어 확인한다.

## 핵심 사용 흐름

1. 선택 정보로 투어 생성 → 샵 추가.
2. 동행인이 실루엣 → 소재 → 상체의 세 단계를 기록한다. 기억 안 남도 유효한 선택이다. 선택은 자동저장하며 화면을 이동시키지 않는다.
3. 소재는 공통으로 고르고, 다를 때만 전환해 상체와 치마를 따로 고른다. 망사·쉬폰은 하나의 선택지다. 상체 단계에는 가슴라인과 끈·소매를 위아래로 각각 노출한다. 허리선·장식·세부 특징은 상세에서 남긴다.
4. 후보·별점·메모 없이도 기록을 완료한다. 완료 화면에서 기억할 특징·좋았던 점·아쉬운 점·느낌·별점을 선택적으로 남긴다. 다음 드레스 기록은 별도 동작이다.
5. 한 벌을 한 건으로 기록한다. 기존 기록에 여러 연출이 있으면 각각 다시 보거나 대표 연출을 고른다. 결과 목록의 전체·후보 필터에서 개별 기록을 연다.
6. 복원 가능한 PDF로 다른 폰에 옮겨 이어 쓰거나 복원 데이터를 뺀 보기 전용 PDF를 저장한다. 새 PDF에는 얼굴을 포함하지 않는다.

## 저장과 복구

- Dexie가 영속 데이터의 기준이며 다중 테이블 변경은 트랜잭션으로 처리한다.
- 유효한 제목·샵명은 자동저장한다. 빈 편집 draft는 저장된 이름을 무효화하지 않으며, 저장 오류에는 복구 안내를 제공한다.
- 사용자 드레스 이름은 착용 순서와 별개로 보존한다. 기본 Dress NN만 순서 변경에 맞게 정리한다.
- 최근 기록 뒤의 더 보기로 과거 투어에 접근한다. 없는 기록 주소와 예기치 않은 화면 오류에는 복귀 동작이 있다.
- 저장 중인 기억 메모는 제한된 sessionStorage draft로 같은 탭에서 복구한다. 기본 연출의 기존 키를 유지하고 추가 연출은 드레스+연출 ID로 격리한다. 전체 삭제는 draft와 캐시를 함께 제거한다.
- Dress 최상위 외형/느낌은 기본 연출, stylingVariants는 추가 연출 스냅샷이다. 후보·별점·이름·착용 순서는 공통이다. 소재는 공통 fabric과 선택적인 upperFabric/lowerFabric으로 저장한다. 두 소재가 다르면 lowerFabricStart에 아래 소재가 시작되는 위치를 기록할 수 있고 기본 위치는 허리다. 표시용 resolve 결과를 통째로 저장하지 않는다. Dexie v1을 유지한다.
- 기존 연출 전환·기록 완료·다음 드레스 생성 전에 마지막 입력까지 저장한다. 실패 시 입력과 현재 연출을 유지하고 재시도한다. coreRecordedAt은 명시적 완료에서 한 번 설정한다.

## 이미지 계약

- 기존 61개 로컬 옵션 이미지는 선택과 용어 설명에 재사용한다. unknown에는 알려진 형태를 임의로 선택하지 않는다.
- 주 그림은 로컬 준비 자산을 합성한 garment-artwork이며 canonical SVG → JPEG/PDF 경로를 공유한다. ready/partial/unavailable/error 상태를 구분한다.
- 전체·상체 미리보기에서 각 영역의 소재를 반영하고 상체 그림이 치마를 덮지 않도록 경계를 맞춘다. 겹친 주름·진주·스팽글·꽃장식은 단추 모양 기호 대신 원단 위 주름·작은 구슬·반짝임·꽃 아플리케로 표현한다.
- 실루엣 참고 이미지는 보조 자료이며 실제 드레스의 모든 특징을 재현했다는 뜻이 아니다.
- 얼굴 입력·미리보기·합성·포함 설정은 제공하지 않는다. 과거 얼굴 포함 PDF는 읽을 수 있지만 새 PDF는 bytes·참조·변환까지 제거한다.
- 4,032개 기본 조합의 구조 테스트는 시각적 정확성의 전수 수용 검증이 아니다. 실제 사용성과 모든 그림 품질을 측정 완료한 것으로 주장하지 않는다.

## 그래픽과 인터랙션

- 사용 순서는 특징 선택 → 느낌 기록 → 기록 다시 보기다. 신규 투어가 유일한 주 행동이며 가져오기는 보조 행동이다.
- 빈 기록·후보 상태는 일관된 노트/옷걸이 모티프를 사용한다. 네크라인·실루엣 도움말은 기존 이미지로 차이를 설명한다.
- 가져오기/내보내기는 폰 → 복원 PDF → 폰 도식을 제공하고 서버 동기화로 오인시키지 않는다.
- 상세는 큰 그림을 유지하면서 저장한 이유로 바로 이동할 수 있다.
- 편집 화면의 미리보기 버튼을 누르면 현재 조합이 모달로 열린다. 닫으면 원래 선택 위치와 포커스로 돌아온다. 선택에 따른 자동 스크롤과 맨 위로 버튼은 없다. 명시적인 이전/다음 단계 이동은 새 단계 제목부터 보여준다.
- 선택·단계·그림·후보·저장 피드백의 짧은 모션은 쓰기·입력·탐색을 지연하지 않는다. 모션 감소 설정에서는 애니메이션을 제거하고 상태·텍스트는 보존한다.

## PDF와 오프라인

- 데이터/manifest는 기본 v1, 추가 연출 v2, 과거 뒤 여밈 v3, 상체·치마 소재 분리 v4, 아래 소재 시작 위치 v5, 손그림 표시 v6를 지원하며 값을 잃지 않는 버전으로 내보낸다. envelope/trailer 형식은 v1을 유지하고 SHA-256 검증 후 v1–v6를 가져온다. copy는 드레스·연출·대표 참조를 함께 재매핑하며 overwrite는 해당 aggregate를 대체한다. PDF 본문은 모든 연출의 전체·상체, 후보 요약은 대표 연출을 표시한다.
- 생성 도중 모드 설정을 잠근다. 생성 결과·파일명·공유 정보는 실제 생성 설정과 일치한다. 이전 작업의 늦은 결과는 현재 화면을 덮지 않는다.
- 표지의 긴 제목과 긴 샵 목록은 페이지 안에서 읽을 수 있도록 분리하고 후보 요약을 제공한다.
- 첫 연결에서 캐시 준비가 완료된 앱은 오프라인 기록·재열기를 지원한다. 준비 여부를 확인할 수 있고 기기 이동 전 PDF 백업을 안내한다.
- PDF 생성 완료와 실제 기기의 파일 저장 성공을 같은 상태로 표시하지 않는다.

## 릴리스 수용 기준

[릴리스 체크리스트](RELEASE_CHECKLIST.md)의 타입·포맷·단위/브라우저 테스트, 카탈로그·의존성 검사와 실제 배포 확인을 충족한다. 320/390px에서 가로 넘침 없이 44px 터치 목표·라벨·포커스가 유지돼야 한다. PDF 개인정보 설정, 저장 실패 복구, 즉시 이동/새로고침, 오프라인과 직접 주소를 포함한다.

브라우저 엔진 자동화는 실물 iPhone/Android 검증을 대신하지 않는다. 당사자·동행인의 현장 입력 속도와 회상/선택 효과는 실제 참여자의 사용성 확인이 필요한 별도 수용 항목이며, 소프트웨어 검사만으로 완료 처리하지 않는다.
