# 드레스 옵션 이미지 자산

드레스 선택 화면은 `public/assets/options/<category>/<id>.webp`에 저장된 25장의 개별 로컬 WebP를 사용합니다. `OptionArtwork.tsx`는 타입이 지정된 URL 맵으로 각 이미지를 렌더링하고, `기억 안 남`은 이미지 요청이 없는 `?` 상태로 유지합니다.

- 실제 디자인 옵션: 25개
- 카테고리: 어깨/끈 6, 넥라인 6, 실루엣 4, 소재 6, 색상 3
- 파일 규격: 모두 512×512 `image/webp`, 파일별 150KB 이하, 합계 3.5MB 이하
- 비주얼 기준: 상체는 턱 바로 아래부터 몸통까지, 얼굴 특징 없음, 정면 중심 구도; 홀터넥은 bib-front 구조; 실루엣은 A라인/벨라인/머메이드/엠파이어를 구분
- 소재/색상 이미지는 빈 여백 없이 프레임을 채우는 매크로/스와치 이미지입니다.
- `public/assets/render-textures/fabric/`의 6개 WebP는 드레스 합성 전용 평면 텍스처입니다. 선택지용 주름진 매크로 이미지는 그대로 두고, 렌더러/PDF만 이 별도 자산을 사용합니다.
- 접근성: 이미지는 `aria-hidden` 장식 요소이고 버튼 텍스트가 실제 옵션명을 제공합니다. 이미지 오류가 나도 버튼 라벨과 터치 영역은 유지됩니다.
- 오프라인: 25개 WebP, OG 카드, 아이콘은 PWA Workbox precache에 포함됩니다.

## 드레스 미리보기

`src/assets/dress-person-illustration-v6.webp`는 투명 배경의 720×1280 로컬 패션 마네킹 일러스트입니다. 큰 가슴·잘록한 허리·부드러운 골반 S곡선의 비너스형 드레스폼이며, 드레스 외곽은 `public/assets/dress-layers/`의 동일 규격 투명 WebP가 결정합니다.

- `bodice/`: 넥라인별 보디스 6개
- `top/`: 끈·홀터·오프숄더·소매 5개
- `skirt/`: 실루엣별 치마 5개
- `volume/`: 공통 그림자·하이라이트와 머메이드·엠파이어 전용 볼륨 4개
- `manifest.json`: 크기, 역할, 바이트, SHA-256 인벤토리

canonical SVG는 경로를 그리지 않고 위 이미지의 알파를 `<mask>`로 사용해 색상과 `render-textures/fabric/` 소재를 자르는 합성 컨테이너 역할만 합니다. 브라우저 미리보기와 JPEG/PDF가 동일 로더와 합성 함수를 사용하며, 배경색으로 신체를 덮는 하체 마스크는 사용하지 않습니다.

레이어를 수정한 뒤에는 `node scripts/generate-dress-layers.mjs`로 20개 WebP와 매니페스트를 함께 갱신합니다. 모든 파일은 720×1280, alpha 포함, 250KB 미만이어야 합니다. `npm run validate:dress-proportions`는 짧은소매/오프숄더 구분도, 마네킹 비율, 보디스·치마 허리 폭을 함께 검사합니다.

## 검증

- 단위 테스트: 25개 정확한 옵션 URL, `기억 안 남` 무이미지 상태, 이미지 오류 fallback, 래스터 드레스 레이어/PDF 인물 합성을 검사합니다.
- 자산 인벤토리: `file`, 디코더, 512×512 크기, 파일별/합계 바이트, 원격 마커, exact path set을 검사합니다.
- 모바일 E2E: 대표 옵션 선택, 320/390px 가로 넘침, 즉시 새로고침 후 선택 유지, 개별 WebP 오프라인 fetch를 검사합니다.
- PDF 왕복 테스트: 복원 가능한 PDF의 원본 데이터/해시와 선택적 얼굴 첨부파일을 실제로 다시 읽어 검증합니다.

Unknown 옵션 파일과 atlas/sprite 파일은 생성하지 않습니다. 옵션 이미지는 앱 라벨과 별도로 렌더링되며, 이미지 안에는 텍스트/워터마크/원격 의존성을 넣지 않습니다.
