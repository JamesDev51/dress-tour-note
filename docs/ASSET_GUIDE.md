# 드레스 옵션 이미지 자산

드레스 선택 화면은 `public/assets/options/<category>/<id>.webp`의 개별 로컬 WebP 61장을 사용합니다. `OptionArtwork.tsx`의 타입 지정 URL 맵이 이미지를 렌더링하고, `기억 안 남`은 이미지 요청 없이 `?`로 표시합니다.

## 카탈로그 계약

- 알려진 선택지: 총 61개
- 9개 카테고리: 어깨/상의 9, 네크라인 8, 실루엣 7, 소재 8, 색상 3, 허리선 4, 등 디자인 6, 트레인 4, 디테일 12
- 파일 규격: 512×512 불투명 `image/webp`, 파일별 120KB 이하, 합계 7.5MB 이하
- `manifest.json`: 61개 경로, 크기, 바이트, alpha 정책, SHA-256 인벤토리
- `contact-sheet.png`: 사람이 전체 카탈로그를 한 번에 확인하는 검수판
- `PROVENANCE.md`: 자산 생성·검수 출처
- 접근성: 이미지는 장식 요소이고 버튼 텍스트가 실제 옵션명을 제공합니다. 로딩 또는 오류 상태에서도 라벨과 터치 영역은 유지됩니다.
- 오프라인: 61개 WebP는 Vite PWA Workbox precache 대상입니다.

임의 ID에는 이미지를 연결하지 않습니다. 알려진 선택지와 정확히 일치하지 않거나 사용자가 `기억 안 남`을 선택한 경우 텍스트 상태를 유지합니다. 가까운 선택지가 없으면 카테고리별 `비슷하지만 달라요` 메모를 별도로 저장하며, 기억 스케치에서도 카테고리와 함께 표시합니다.

## 드레스 기억 스케치

기본 미리보기는 `public/assets/garment/`의 로컬 WebP를 기록한 특징에 맞춰 조합합니다. `src/lib/renderer/garment/`에서 준비한 결과를 `src/lib/renderer/dressSvg.ts`의 SVG 프레임에 배치하며, 준비할 수 없는 경우 기록 스케치를 표시합니다.

- 뷰: 전체(`full`), 상체(`upper`), 뒤태(`back`)
- 반영 항목: 어깨/상의, 네크라인, 실루엣, 소재, 색상, 허리선, 등 디자인, 트레인, 디테일과 선택지 밖 메모
- 미기록 값: 임의 추정 대신 점선과 `미기록`으로 표시
- 얼굴: 명시적으로 포함한 전체·상체 뷰에만 합성하며 뒤태에는 포함하지 않음
- 일관성: 브라우저 미리보기와 PDF/JPEG 파생물이 같은 SVG 생성 함수를 사용

선택지 카탈로그 61장과 드레스 조합용 자산은 별도로 유지합니다. 조합 결과는 `ready`, `partial`, `unavailable` 상태를 명시하며, 미기록 특징을 임의로 채우지 않습니다. 브라우저는 로컬 자산 경로를 사용하고 PDF/JPEG는 같은 자산을 포함해 렌더링합니다. 조합 자산도 배포 및 오프라인 검증 대상입니다. 휴대용 v1 JSON에는 새 이미지 ID나 조합 이미지 바이트를 추가하지 않습니다.

## 검증

```bash
npm run validate:option-catalog
npm run test:option-catalog-validator
npm test
npm run build
npm run test:e2e
```

`validate:option-catalog`는 정확한 61개 경로, WebP 형식, 512×512 크기, 불투명 정책, 개별·전체 용량, 중복 해시, 원격 마커, 매니페스트 일치와 Workbox 적격성을 검사합니다. adversarial validator 테스트는 누락, 추가, 손상, 중복, 잘못된 크기, 과대 파일을 각각 거부하는지 확인합니다. 단위 테스트는 URL 매핑, `기억 안 남`, 이미지 로딩·오류 fallback과 기억 스케치의 전체·상체·뒤태 동작을 검사합니다. E2E는 61개 실제 WebP, 오프라인 fetch, 외부 요청 부재, 320px/390px 화면과 전체 axe 표면을 검사합니다.
